## Лабораторная: Решение проблемы "is not in the sudoers file"

### Симптом:
После добавления пользователя в группу `sudo` через `usermod -aG`, команда `sudo` всё равно выдавала ошибку доступа.

### Причина:
Текущая оболочка (shell) кэширует список групп пользователя на момент своего запуска. Она не обновляется автоматически после изменения `/etc/group`.

### Решение:
1. Проверка актуальных групп через `groups` (убедиться, что `sudo` присутствует).
2. Полное переподключение к сессии (`su - balthazar` или перезапуск терминала/SSH).
3. (Резервный метод) Прямое добавление правила в `/etc/sudoers` через безопасный редактор `visudo`:
   `balthazar ALL=(ALL:ALL) ALL`

### Вывод:
Изменение прав пользователя требует либо перезапуска сессии, либо прямого редактирования конфигурации sudo. Всегда используй `visudo` для редактирования `/etc/sudoers`, чтобы избежать синтаксических ошибок, блокирующих доступ.
